# Runtime compatibility matrix

Status as of repository commit `2e912b5` (2026-10-18). Built only from committed documents and raw benchmark files; every number carries
`file@commit` (the last commit that touched the file, `git log -1 -- <file>`). Nothing was re-measured for this document. Detailed
reasoning and the decision view are in `feasibility-report.md`.

## How to read the status words

- **VERIFIED**: measured with the real TingMix weights against the PyTorch CPU fp32 oracle (or measured on the real artifact),
  inside the scope stated in the same cell. The scope is almost always the 8 synthetic TTS fixtures (`tests/fixtures/audio`),
  never a real-speech accuracy set.
- **EXPERIMENTAL**: implemented or officially supported, but speed, real-speech accuracy, deployment (signing, clean machine) or
  the whole path is not (fully) established, or the evidence is synthetic or pipeline-only (random weights).
- **BLOCKED**: a hard blocker remains (missing artifact, hardware or permission).
- "Not run" or "not measured" means nothing was attempted; it is not a failure.

A backend row carries one overall word; the specific claims inside it carry their own. So a backend can be EXPERIMENTAL overall while
"output text equals the oracle on 8/8 clips" is VERIFIED.

Hardware. Apple: Mac Studio, Apple M4 Max 40-core GPU, 64 GB, macOS 27.0. Windows: Ryzen 7 9700X 8C/16T, 62 GB, NVIDIA RTX 5070 Ti 16 GB,
Windows 11 26200 (`docs/release/windows-validation.md@090f734`). One machine of each; other processes ran during most runs (loadavg 7 to 16
on the Mac), so latencies are indicative (`benchmarks/apple/mlx/README.md@36eb69e`, `docs/research/mlx-cpp-ffi.md@7e6d484`).

Pins: TingMix-Large `75071a1`, google/embeddinggemma-2 `914f7f8`, tingmix `f44cbdb`, embed2asr `b582757` (`docs/research/PINNED.md@93c309d`).
